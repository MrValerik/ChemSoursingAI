# Структура репозитория

Раскладка следует блочной архитектуре из ТЗ. Ниже показано фактическое состояние
репозитория; целевые компоненты, которые ещё не реализованы, отмечены отдельно.

```
ChemSoursingAI/
├── backend/                  # L1–L3, L7: API, прикладные сервисы, оркестрация, данные
│   └── app/
│       ├── api/              # L1: HTTP-эндпоинты (BFF/API Gateway)
│       ├── core/             # конфиг, настройки, общие утилиты
│       ├── models/           # L7: ORM-модели (сущности из ТЗ)
│       ├── schemas/          # Pydantic-схемы запросов/ответов и JSON-схема котировки
│       ├── services/         # L2: бизнес-логика (RFQ, котировки, эскалации, шаблоны)
│       ├── connectors/       # L5: адаптеры внешних интеграций (PubChem, Email, web)
│       └── extraction/       # L3–L4: structured output, правила, валидаторы, LLM
│   ├── tests/                # pytest: API, бизнес-правила и интеграционные контракты
│   └── scripts/              # локальный сквозной demo-поток
├── frontend/                 # L1: SPA — рабочее место специалиста (React + TS)
├── ml/                       # резерв под отдельные ИИ-артефакты и eval
├── data/
│   └── synthetic/            # синтетический корпус писем для отладки без боевых доступов
├── deploy/                   # systemd и конфигурация ВМ
├── docs/                     # продуктовая, архитектурная и эксплуатационная документация
├── docker-compose.yml        # Postgres, Redis, backend и frontend
└── AGENTS.md                 # постоянные цели и правила работы Codex
```

## Принципы

- **Слабая связанность.** Внешние интеграции скрыты за слоем `connectors` с единым интерфейсом и fallback — смена провайдера не затрагивает ядро.
- **LLM через OpenAI-совместимый API.** Смена модели (llama-server → vLLM) — изменение конфигурации, а не кода.
- **Конфигурация извне.** Все параметры — через переменные окружения (см. `.env.example`).
- **Проверяемость.** Выводы о веществе и поставщике сопровождаются источником,
  уверенностью и причиной статуса.
- **Безопасный внешний контур.** Отправка по умолчанию выключена или создаёт
  черновик; интеграции включаются явно.

## Целевые компоненты

Следующие элементы предусмотрены архитектурой, но не должны считаться
реализованными только по наличию каталога или записи в ТЗ:

- отдельные воркеры и промышленная очередь задач;
- объектное хранилище и антивирусная обработка вложений;
- OCR/vision-конвейер;
- pgvector/RAG и golden-датасет реальных писем;
- коннекторы WhatsApp, WeChat и Echemi;
- Kubernetes и полный стек метрик/трейсов.
