# Локальный Telegram-агент Codex

Telegram-агент позволяет владельцу проекта задавать вопросы о ChemSource AI и
явно поручать исправления, пока Windows-компьютер включён и подключён к интернету.
Он работает отдельным локальным процессом через Telegram Bot API long polling;
входящий порт, публичный HTTP-сервер и белый IP не нужны.

## Почему не используется `amintikk/codex-telegram`

Из готового проекта взята удачная общая идея: Telegram как транспорт,
долгоживущая сессия и запуск официального Codex. Сам контейнер не используется:
его типовая конфигурация даёт процессу `privileged`, host PID/network, Docker
socket, корневую файловую систему хоста и `danger-full-access`. Кроме того,
host-shell реализован Linux-командой `nsenter` и не может штатно управлять
PowerShell, Windows Python, Docker Desktop, Yandex Cloud CLI и `.cmd`-скриптами
этого проекта.

Реализация в `tools/telegram-agent` использует официальный Python SDK
`openai-codex`, который включает совместимый Codex runtime и переиспользует
локальную авторизацию Codex. Режим `/ask` строго read-only; `/fix` получает
`workspace-write` и автоматическую проверку запросов разрешений, после чего
следует правилам корневого `AGENTS.md`.

## Подготовка

Нужны:

- Python 3.10 или новее и Windows Python Launcher `py.exe`;
- выполненный вход в Codex на этом Windows-пользователе;
- Telegram-бот, созданный через `@BotFather`;
- числовой Telegram `user_id` владельца (например, его можно узнать через
  `@userinfobot`). Это именно user ID, не username и не chat invite link.

Из корня чистого checkout выполните:

```powershell
.\deploy\setup-telegram-agent.cmd
```

Скрипт создаст изолированное окружение
`tools\telegram-agent\.venv`, установит закреплённые зависимости и создаст
игнорируемый Git файл `tools\telegram-agent\.env`.

Desktop-приложение и SDK могут использовать разные локальные хранилища сессии.
Если SDK ещё не авторизован, выполните device-code login и следуйте подсказке:

```powershell
.\deploy\login-telegram-agent-codex.cmd
```

Затем заполните в `.env` минимум:

```dotenv
TELEGRAM_BOT_TOKEN=токен_из_BotFather
TELEGRAM_ALLOWED_USER_IDS=123456789
TELEGRAM_PROJECT_ROOT=E:\MyProjects\TechLab\ChemSoursingAI
```

Пустой allowlist не означает «разрешить всем»: агент аварийно завершит запуск.
Допускаются несколько user ID через запятую, однако агент всё равно принимает
сообщения только из приватных чатов.

## Запуск

Для первого запуска и просмотра журнала в консоли:

```powershell
.\deploy\start-telegram-agent.cmd
```

После проверки установите автозапуск при входе текущего Windows-пользователя:

```powershell
.\deploy\install-telegram-agent-task.cmd
```

Планировщик запускает процесс от текущего пользователя, чтобы ему были доступны
локальная авторизация Codex, Git/SSH, Docker Desktop и Yandex Cloud CLI. Компьютер
должен быть включён, пользователь должен войти в Windows, а спящий режим должен
быть отключён на нужное время.

## Команды

- `/ask вопрос` — прочитать проект, диагностировать и ответить без изменений;
- обычный текст — то же, что `/ask`;
- `/fix задача` — выполнить изменение по `AGENTS.md`, включая проверки,
  commit/push/deployment только при успешном результате;
- `/status` — показать активную задачу, ветку и чистоту рабочего дерева;
- `/stop` — запросить прерывание активного turn;
- `/new` — забыть текущую сессию и начать следующую с чистым контекстом;
- `/help` — показать справку.

Поддерживаются фотографии и документы PNG/JPEG/WebP, а также небольшие `.txt`,
`.log`, `.md`, `.json`, `.yaml`, `.yml`, `.csv`. Вложения сохраняются под
случайным именем, проверяются по размеру и для изображений — по сигнатуре,
передаются Codex как недоверенные данные и удаляются после завершения задачи.

## Границы безопасности

- токен хранится только в игнорируемом `.env` и редактируется из ответов/ошибок;
- Telegram update offset сохраняется до обработки команды: после аварийного
  перезапуска опасная `/fix` не должна выполниться повторно;
- одновременно выполняется только одна задача;
- `/ask` не может менять workspace и не получает разрешений;
- `/fix` является явным разрешением владельца на изменение в пределах проекта,
  но не отменяет проверки чистого `main`, тестов и прочих ограничений `AGENTS.md`;
- бот не принимает команды из групп и молча игнорирует чужие user ID;
- содержимое присланных файлов не считается инструкцией.

Telegram Bot API и Codex остаются внешними сервисами: текст запросов и вложения,
переданные в `/ask` или `/fix`, покидают локальный компьютер. Не отправляйте в бот
пароли, токены, `.env`, реальные коммерческие предложения или персональные данные.

## Проверка агента

```powershell
Push-Location .\tools\telegram-agent
try {
    .\.venv\Scripts\python.exe -m unittest discover -s tests -v
} finally {
    Pop-Location
}
```

Тесты используют заглушки Telegram и Codex и не обращаются во внешнюю сеть.
