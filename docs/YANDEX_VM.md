Скрипт использует профиль Yandex Cloud CLI текущего пользователя. Токены и
идентификаторы профиля в репозиторий не записываются.

## Проверка состояния

Из корня репозитория:

```powershell
.\deploy\yc-vm.cmd status
```

Команда только читает состояние и не требует подтверждения.

## Запуск

```powershell
.\deploy\start-server.cmd
```

Скрипт:

1. покажет подтверждение начала тарификации вычислительных ресурсов;
2. запустит ВМ;
3. дождётся статуса `RUNNING`;
4. дождётся ответа `http://<IP>/api/health` — то есть реальной готовности
   сайта, а не только виртуальной машины (Docker-стек и Qwen поднимаются
   несколько минут после загрузки);
5. отдельно сообщит, готова ли локальная ИИ-модель;
6. с `-OpenSite` откроет сайт в браузере только после готовности.

Если ВМ работает, а сайт так и не ответил, скрипт завершится с ошибкой и
покажет команды диагностики. Это значит, что на ВМ не поднялся автозапуск
сервисов — выполните на ней `sudo bash deploy/install-vm-services.sh` или
`sudo systemctl enable --now qwen.service chemsource.service`. Каждое
развёртывание `update-server.cmd` теперь переподтверждает автозапуск, поэтому
ВМ, запущенная вручную из консоли Yandex Cloud, тоже поднимает сайт сама.

Чтобы после запуска открыть сайт:

```powershell
.\deploy\start-server.cmd -OpenSite
```

После запуска systemd должен автоматически поднять Docker Compose и Qwen.
Проверка внутри ВМ:

```bash
systemctl is-active qwen.service chemsource.service
docker compose ps
curl http://127.0.0.1/api/health
curl http://127.0.0.1/api/health/llm
```

## Остановка

```powershell
.\deploy\stop-server.cmd
```

Команда выполнит штатную остановку и дождётся статуса `STOPPED`.

## Переопределение ВМ

По умолчанию используется ВМ проекта. Для другой ВМ передайте ID:

```powershell
.\deploy\yc-vm.cmd status -InstanceId "<instance-id>"
```

## Автовыключение и разработка

На сервере установлен таймер выключения после 30 минут без HTTP-активности.
Обычное SSH-соединение активностью не считается. Перед долгой работой только по
SSH временно остановите таймер:

```bash
sudo systemctl stop chemsource-idle-shutdown.timer
```

После работы включите его:

```bash
sudo systemctl start chemsource-idle-shutdown.timer
systemctl is-active chemsource-idle-shutdown.timer
```

Или остановите ВМ скриптом с локального компьютера.

## Типовой цикл разработки

Локально:

```powershell
git pull --ff-only
# изменения через Codex
git push origin main
.\deploy\update-server.cmd
```

`update-server.cmd` является штатным способом развёртывания. Он:

1. требует чистую локальную ветку `main`;
2. получает изменения `origin/main` и автоматически выполняет rebase;
3. отправляет локальные коммиты командой `git push origin main`;
4. при конфликте отменяет rebase и не запускает ВМ;
5. запускает остановленную ВМ и дожидается SSH;
6. запрещает обновление поверх неизвестных изменений на сервере;
7. выполняет fast-forward до переданного commit SHA;
8. создаёт резервную копию PostgreSQL;
9. применяет ещё не применённые `backend/migrations/*.up.sql`;
10. пересобирает Compose-стек и проверяет backend, frontend и локальную ИИ;
11. восстанавливает таймер автоостановки.

Параметры подключения можно переопределить:

```powershell
.\deploy\update-server.cmd `
  -SshUser "valerik" `
  -SshKeyPath "C:\Users\<user>\.ssh\id_ed25519"
```

Для запуска у каждого разработчика должны быть собственный профиль `yc`,
доступ к облаку и собственный SSH-ключ, добавленный на ВМ. Секреты и приватные
ключи в Git не хранятся.

## Команды Codex

В репозитории доступны три отдельные команды:

- `$update` — обновить код, миграции и контейнеры;
- `$start-server` — включить ВМ без обновления кода;
- `$stop-server` — штатно выключить ВМ.

В `/skills` они отображаются как «Обновить сервер», «Запустить сервер» и
«Остановить сервер». Вызов `$update` одновременно разрешает отправку уже
созданных локальных коммитов из чистой ветки `main`. Незакоммиченные изменения
команда не фиксирует.

Описание показывается в списке skills. Устаревшие локальные `/prompts:*` не
используются, потому что они не распространяются через репозиторий.
